## 4. 主线：契约驱动

这是全仓最核心的设计。

```
contracts/http/openapi.yaml  (手写，$ref 拆分到 paths/ 与 components/)
        │  task bundle-spec → vacuum bundle --composed --base contracts/http
        ▼
contracts/http/dist/openapi.yaml  (打包制品，首行写 "# Generated by task bundle - do not edit manually")
        │
        ├── task codegen-python → datamodel-codegen
        │       └→ apps/server/src/server/generated/contracts.py
        │
        └── task codegen-typescript → bunx orval
                └→ apps/web/src/api/generated/{http/,schemas/}
```

### 4.1 契约本身

契约只有 `GET /healthz` 一个端点，但把规范立全了：

* 统一响应信封 `{code, message, data}`，且 `additionalProperties: false`
* 响应用 `allOf` 组合信封 + 具体 data
* `contracts/ruleset.yaml` 把 vacuum 的 `camel-case-properties`、`paths-kebab-case`、`operation-description` 等提为
  error
* 自定义 `no-sensitive-examples` 规则，对 12 个 JSONPath 断言 `example/examples/default` 必须为空

### 4.2 契约到运行时的强约束落地

| 契约声明                               | 生成结果                                         |
| -------------------------------------- | ------------------------------------------------ |
| `additionalProperties: false`          | Pydantic `ConfigDict(extra='forbid')`            |
| `code: integer` + `--strict-types int` | `code: StrictInt`                                |
| `allOf[Response, {...}]`               | `HealthzGetResponse(Response)` 覆写 `data: Data` |
| `enum: [ok]`                           | `class Status(Enum): ok = 'ok'`                  |

### 4.3 漂移防护

`check-codegen` = 重新生成 + `git diff --exit-code -- {{.GENERATED}}`，`GENERATED` 同时覆盖 Python 模型、Web 客户端、zod
schema 与 dist 制品（`Taskfile.yaml:29`）。生成物全部**提交入库**，任何一端不同步都会红。

## 5. 部署拓扑

```
                 ┌──────────────────────────────┐
:80 / :443  ────▶│  web 容器（Caddy）            │
                 │  /assets/* → 长缓存 immutable │
                 │  其余      → no-cache         │
                 │  /healthz  → reverse_proxy    │
                 └───────────┬──────────────────┘
                             │ internal 网络
                             ▼
                 ┌──────────────────────────────┐
                 │  api 容器（granian）          │
                 │  GET /healthz                 │
                 └──────────────────────────────┘
```

* `api` 只声明镜像不构建，启动前必须先 `task build-image`
* `web` 通过 `depends_on: api: condition: service_healthy` 等待后端就绪
* 站点域名是 `web.<AUTH_DOMAIN>`，`AUTH_DOMAIN` 是历史命名
* 日志驱动为 `journald`，健康检查间隔 10s / 超时 5s / 重试 5 次 / 启动宽限 30s
